DIG Relay — STUN

A RFC 5389 STUN Binding responder for the DIG Network — it exists so a NAT'd node can learn its own reflexive (public-facing) address and port before it tries to negotiate a direct peer connection.

Endpoint

{{HOST}}:3478UDP

This one hostname answers correctly over both address families: an IPv4-only caller resolves the A record to a same-family IPv4 responder, an IPv6 caller resolves AAAA to a same-family IPv6 responder. Either way you get back a reflexive address in the family you actually dialed with — never the load balancer's own address standing in for yours.

Try it

stunclient {{HOST}} 3478

Any RFC 5389 Binding client works — for example stunclient, packaged on most Linux distributions as stuntman-client. A correct response reports your own address:port straight back to you.

What this is not

  • Not a general-purpose public STUN service for projects outside the DIG Network.
  • Not a proxy or relay for arbitrary UDP traffic.
  • Not a destination for anything but a STUN Binding request — other datagrams are dropped.

Authorization

No authentication or signed request is required to send a Binding request today.
